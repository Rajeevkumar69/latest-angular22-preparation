Angular Component Lifecycle

Angular calls at different stages of a component's life cycle. These hooks allow developers to execute specific code at specific points such as when a component is initialized, updated or destroyed.

Create

Angular creates an instance of the component.

Initialize

The component is set up and initialized.

Change Detection

Angular checks for changes in data and inputs.

Render

The component is rendered on the web page.

Destroy

The component is cleaned up and removed.

Angular manages the component through these stages.

Lifecycle Execution Order
Constructor 1. ngOnChanges 2. ngOnInit 3. ngDoCheck 4. ngAfterContentInit 5. ngAfterContentChecked 6. ngAfterViewInit 7. ngAfterViewChecked afterNextRender afterEveryRender 8. ngOnDestroy

Constructor is not a lifecycle hook. Render callbacks are separate from lifecycle hooks and do not have a fixed numbered position in the lifecycle sequence.

Initialize
1. ngOnChanges

This hook runs whenever an input property changes. It also runs when Angular initializes the component's input properties, before ngOnInit.

When: Whenever an input property changes.

Use case: Responding to changes in component inputs.

2. ngOnInit

This hook runs once after Angular initializes the component's input properties.

When: Once, after the first ngOnChanges.

Use case: Component initialization logic, preparing initial data and calling APIs.

Change Detection
3. ngDoCheck

This hook allows developers to implement custom change detection logic.

When: Frequently during Angular change detection.

Use case: Detecting changes that Angular's normal change detection may not handle as required.

4. ngAfterContentInit

This hook runs once after Angular initializes the content projected into the component using ng-content.

When: Once, after projected content initialization.

Use case: Accessing projected content after initialization.

5. ngAfterContentChecked

This hook runs whenever Angular checks the projected content of the component.

When: During every relevant projected-content check.

Use case: Responding after Angular checks projected content.

6. ngAfterViewInit

This hook runs once after Angular initializes the component's view and child views.

When: Once, after the component view is initialized.

Use case: Working with child components and view elements after initialization.

7. ngAfterViewChecked

This hook runs whenever Angular checks the component's view and child views.

When: During every relevant view check.

Use case: Responding after Angular checks the component view.

Avoid heavy operations inside ngDoCheck, ngAfterContentChecked and ngAfterViewChecked because these hooks can execute frequently.
Render
afterNextRender

This is a modern Angular render callback, not a lifecycle hook. It runs after Angular completes the next render.

When: Once, after the next render.

Use case: Performing one-time DOM-related operations after rendering.

afterEveryRender

This is another modern Angular render callback, not a lifecycle hook. It runs after every Angular render.

When: After the initial render and every subsequent render.

Use case: Performing operations that need to happen after each render.

Both render callbacks run in the browser, not during server-side rendering (SSR).
Destroy
8. ngOnDestroy

This hook runs just before Angular destroys a component.

When: Before the component is destroyed.

Use case: Cleanup tasks such as clearing timers, unsubscribing from subscriptions and releasing resources.

DestroyRef

DestroyRef is a modern Angular API that allows developers to register cleanup logic when the component or service is destroyed.

When: Its onDestroy callback executes when the associated lifecycle scope is destroyed.

Use case: Handling cleanup without implementing ngOnDestroy. It keeps cleanup logic close to the code that creates the resource.

Important Points to Remember
  • Constructor executes before Angular lifecycle hooks.
  • ngOnChanges executes before ngOnInit during initial initialization.
  • Init hooks execute only once.
  • Check hooks can execute multiple times during change detection.
  • afterNextRender and afterEveryRender are render callbacks, not lifecycle hooks.
  • Both render callbacks execute in the browser, not during SSR.
  • Signals react to state changes; lifecycle hooks handle specific stages of a component's lifecycle.
  • We don't need to implement every lifecycle hook in every component.
