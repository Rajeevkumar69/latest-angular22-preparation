HTTP Interceptors

Centralized HTTP Request & Response Management

HTTP Interceptors allow us to handle common logic for multiple HTTP requests in one place, instead of repeating the same code in different services.

Why use HTTP Interceptors?

Interceptors sit between your Angular application and the backend API. They can inspect or modify outgoing requests and incoming responses before they reach their destination.

Common Use Cases
Authentication

Attach authentication tokens to outgoing API requests.

JWT Authorization

Send JWT access tokens through the Authorization header.

Global Error Handling

Handle common HTTP errors such as 401, 403 and 500.

Loading Indicators

Manage global loading indicators during HTTP requests.

Retry Logic

Retry failed requests when appropriate.

Caching

Cache suitable HTTP responses to reduce unnecessary API calls.

Types of HTTP Interceptors

Angular supports two approaches for implementing HTTP interceptors.

01 Recommended
Functional Interceptors

Functional interceptors use the HttpInterceptorFn type and are implemented as standalone functions. They are the recommended approach for modern Angular applications.

Key Characteristics

  • Function-based implementation
  • Uses HttpInterceptorFn
  • Supports inject() for dependency injection
  • Configured using withInterceptors()
02 Traditional
DI-based / Class Interceptors

DI-based interceptors use the HttpInterceptor interface and class-based implementation. They follow the traditional Angular interceptor approach.

Key Characteristics

  • Class-based implementation
  • Implements HttpInterceptor
  • Uses constructor dependency injection
  • Configured using HTTP_INTERCEPTORS provider
