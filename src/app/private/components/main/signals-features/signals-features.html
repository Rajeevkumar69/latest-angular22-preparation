Angular Signals

Manage reactive state and build efficient, responsive applications.

Component Communication Using Signals

Angular provides 5 different ways to communicate and share data between components.

01
input()
Parent → Child

Passes data from a parent to its child component.

Example

Display parent component data inside a child component.

02
output()
Child → Parent

Sends data or events from a child to its parent component.

Example

Emit child form data to the parent when the Save button is clicked.

03
model()
Two-way

Enables two-way data binding between parent and child components.

Example

Update a value in the child and automatically reflect the change in the parent.

04
Service + signal()
Unrelated

Shares reactive state between components that do not have a direct parent-child relationship.

Example

Share logged-in user information between Header and Dashboard components.

05
viewChild()
Parent → Child Reference

Accesses a child component instance, its properties, and its methods from the parent component.

Example

Call a child component's resetForm() method directly from the parent component.

1. What are Signals?

A Signal is a reactive wrapper around a value that Angular can track. When its value changes, Angular knows which parts of the application depend on it.

count = signal(0);

Read a signal by calling it as a function. Angular automatically updates the template when the signal changes.

2. Why do we need Signals?
Reactive State Management

Manage application state reactively.

Automatic UI Updates

Update dependent template expressions when state changes.

Precise Reactivity

Track which signals are read by dependent computations and views.

Modern State Management

Build reactive features with Angular's built-in APIs.

3. Creating Signals

Signals can store different types of values.

count = signal(0);

name = signal("ABC");

isLoggedIn = signal(true);

items = signal<string[]>(["ABC", "BCD"]);

user = signal({
     name: "John",
     age: 28
});

5. Types of Signals

Angular provides two main types of signals.

Writable Signal

Created using signal(). Its value can be read and modified using set() and update().

count = signal(0);

count.set(10);

count.update(value => value + 1);
Computed Signal

Created using computed(). Its value is derived from other signals and is read-only.

price = signal(100);
quantity = signal(2);

total = computed(
     () => this.price() * this.quantity()
);
6. Advanced Signals
Computed Signal

A computed signal derives its value from one or more existing signals. Angular tracks its dependencies automatically.

Calculated Total

{{ total() }}

total = computed(
     () => this.price() * this.quantity()
);
Effect API

effect() runs a side-effect function when signals read inside it change. It is useful for logging, analytics and synchronizing with external APIs such as browser storage. 

effect(() => {
     console.log('Theme:', this.theme());

     localStorage.setItem(
          'theme',
          this.theme()
     );
});
asReadonly() API

Creates a read-only view of a writable signal. Consumers can read its value but cannot modify it using set() or update(). 

count = signal(0);

readOnlyCount = this.count.asReadonly();

8. Important Notes
Computed()
  • Derived State: Creates a value based on one or more existing signals.
  • Lazy Evaluation: The computed value is evaluated when it is read.
  • Memoization: Angular caches the result until its dependencies change.
  • Read-Only: Cannot be directly modified using set() or update().
  • Dynamic Dependencies: Only signals actually read during the latest computation are tracked.
Effect()
  • Reactive Side Effect: Runs in response to changes in signals it reads.
  • Logging: Useful for debugging and application monitoring.
  • External Synchronization: Can synchronize state with browser APIs such as localStorage.
  • Effects are not intended for propagating state changes between signals.
asReadonly()
  • Creates a read-only view of a writable signal.
  • Prevents consumers from directly calling set() or update().
  • The original signal remains writable by its owner.
  • Allows other parts of the application to read state without modifying it.
