Angular Routing

Understand how Angular navigates between different pages without reloading the entire application.

What is Angular Routing?

Angular Routing is a feature that allows users to navigate between different views or components of an application without refreshing the entire browser page.

It maps a URL path to a specific Angular component.

1. Why do we need Angular Routing?

Routing helps us build Single Page Applications (SPA) with multiple views.

  • Navigate between different components.
  • Avoid full-page browser reloads during navigation.
  • Support URL-based navigation.
  • Pass data through route parameters.
  • Protect routes using Route Guards.
  • Load components only when required using Lazy Loading.
2. Basic Routing Configuration

Routes define which component should be displayed for a particular URL path.

app.routes.ts

import { Routes } from '@angular/router';
import { HomeComponent } from './home/home.component';
import { AboutComponent } from './about/about.component';

export const routes: Routes = [
     {
          path: 'home',
          component: HomeComponent
     },
     {
          path: 'about',
          component: AboutComponent
     }
];
3. Router Outlet

Router Outlet is a placeholder where Angular displays the component matching the current route. 

<nav>
     <a routerLink="/home">Home</a>
     <a routerLink="/about">About</a>
</nav>

<router-outlet></router-outlet>
4. RouterLink

RouterLink is a directive used to navigate between routes without reloading the entire page. 

<a routerLink="/home">Home</a>
<a routerLink="/about">About</a>

<button (click)="goToHome()">
     Go To Home
</button>

TypeScript

import { Router } from '@angular/router';

constructor(private router: Router) {}

goToHome() {
     this.router.navigate(['/home']);
}

RouterLink is used in HTML, whereas Router.navigate() is used for programmatic navigation in TypeScript.

5. Route Parameters

Route Parameters are used to pass dynamic values through the URL, such as a user ID or product ID.

Route Configuration

{
     path: 'user/:id',
     component: UserComponent
}

HTML

<a [routerLink]="['/user', 101]">
     View User
</a>

TypeScript

import { ActivatedRoute } from '@angular/router';

constructor(private route: ActivatedRoute) {
     const userId = this.route.snapshot.paramMap.get('id');
     console.log(userId);
}
Example

/user/101 → User ID: 101

6. Query Parameters

Query Parameters are used to pass optional information through the URL, usually for filtering, searching or pagination. 

<a [routerLink]="['/products']"
   [queryParams]="{ category: 'mobile', page: 1 }">
     View Products
</a>

TypeScript

constructor(private route: ActivatedRoute) {
     this.route.queryParamMap.subscribe(params => {
          console.log(params.get('category'));
          console.log(params.get('page'));
     });
}
Example URL

/products?category=mobile&page=1

7. Wildcard Route

A Wildcard Route uses ** to match any URL that does not match the defined routes. It is commonly used to display a Page Not Found component. 

{
     path: '**',
     component: PageNotFoundComponent
}

Important: Always define the wildcard route at the end of the routes array.

8. Child Routes (Nested Routing)

Child Routes allow us to define routes inside another route. They are useful for creating layouts with nested views, such as a dashboard with multiple sections. 

{
     path: 'dashboard',
     component: DashboardComponent,
     children: [
          {
               path: 'profile',
               component: ProfileComponent
          },
          {
               path: 'settings',
               component: SettingsComponent
          }
     ]
}
{
     path: 'dashboard',
     component: DashboardComponent,
     canActivate: [authGuard]
}

Note: Client-side guards are not a security boundary. The backend must also enforce authorization.

10. Lazy Loading

Lazy Loading loads a feature's code only when the user navigates to that route. It helps reduce the initial application loading cost. 

{
     path: 'admin',
     loadComponent: () =>
          import('./admin/admin.component')
               .then(m => m.AdminComponent)
}

This example uses loadComponent for a standalone component. Feature route configurations can also be lazy-loaded using loadChildren.
